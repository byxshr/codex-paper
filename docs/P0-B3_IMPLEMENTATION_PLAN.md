# P0-B3 Implementation Record

## Objective

P0-B3 upgrades the existing `.codex-paper/validation-report.json` in place to Validation Report `1.0.0` and makes evidence, facts, analysis, reasoning, and user-visible materials participate in one deterministic consistency gate.

The implementation deliberately does not add identity, generation manifests, transactional publication, migration APIs, parser improvements, or generated-code execution.

## Implemented design

- Added a strict JSON Schema and a shared report engine used by the reasoning and study-package CLIs.
- Added intrinsic `pass | pass_with_warnings | fail`, `draft | complete`, `publishable`, explicit scope, structured findings, reference coverage, stable intrinsic hash, and standard/strict gate semantics.
- Added cross-artifact checks for direct/legacy references, ResultClaim projections, numeric divergence, visible metric-bound results, conflict disclosure, front-matter contamination, and explicit parser degradation.
- Preserved 2.0 read compatibility and v1 limited validation while keeping unsupported versions and corrupt authoritative metadata fail closed.
- Migrated the mandatory fixtures from expected P0-B3 defects to positive Validation Report 1.0 assertions.
- Added the authenticated, no-store Viewer Validation API and a read-only quality panel with evidence navigation.
- Added `validation-test`, CI ordering, Repository Guard sentinels/mutations, contract documentation, and skill workflow updates.

## Validation sequence

The intended package workflow is:

1. Run reasoning validation and require an `allow_authoring` draft gate.
2. Write and review visible materials.
3. Run complete validation under the standard policy.
4. Optionally run strict validation when warnings should block that invocation.

Strict mode never rewrites intrinsic status, findings, publishability, or report hash.

## Safety and rollback

Only `.codex-paper/validation-report.json` is writable. Writes reject symlink boundaries and use an fsynced no-follow temporary file followed by atomic rename. v1 and unsupported packages do not receive a 1.0 report.

Rollback is a normal Git revert of the P0-B3 changes. There is no package migration to reverse. Existing reports may be regenerated by the prior validator after rollback.

## Acceptance

Local acceptance requires:

- Validation Report unit/security/compatibility tests.
- Mandatory `2/2` with strict blocking and final standard reports.
- Repository, study, PDF, parser, reasoning, package, build, Viewer security, and smoke regressions.
- Official plugin validation, cachebuster update, reinstall, and active-path confirmation.
- Browser QA against an isolated temporary paper library.

P0-B3 remains `开发完成 / 未推送` after local acceptance. M1 does not formally close until independent Review and remote CI both pass.

# Generation Publication 1.0

Generation Publication 1.0 turns one exact validated workspace into a sealed managed generation. It uses the C2a no-follow writer and hierarchical locks; it does not claim filesystem-wide multi-file atomicity.

The commit sequence is `sealed workspace → generation rename → current.json → index.json`. The generation rename makes immutable bytes durable, while `current.json` makes them authoritative and Viewer-visible. `index.json` is a cache and can always be rebuilt from records/current/manifests.

`.codex-paper/generation-manifest.json` is authoritative for generated bytes. It inventories every regular package file except itself and binds the identity and Validation Report hash. `current.json` binds the raw manifest file SHA-256. Resolvers verify that binding for C2b generations; drift fails closed as `GENERATION_MANIFEST_DIRTY` or `GENERATION_MANIFEST_INVALID`. Pre-C2b managed generations without manifest fields remain explicit unsealed compatibility records.

`publication.json` is a private recovery journal inside the generation workspace, not a generation artifact. It never contains an absolute path. States are `prepared`, `generation_committed`, `current_committed`, `index_committed`, and `failed`. Recovery accepts only an exact valid journal/workspace pair and reruns the idempotent transaction under the same lock order.

Publication requires a complete standard Validation Report whose intrinsic hash is valid and whose gate outcome is `allow_publish`. Strict reports, drafts, failed reports, missing reports, and reports with a mismatched hash cannot publish.

Successful publication preserves the paper overlay. Changing tags, chat notes, progress, annotations, or generation-scoped sandbox reports does not change the manifest. Generated package writes after publication are rejected; manual drift is detected during authoritative resolution.

Index rebuild uses two integrity tiers. It validates the small authoritative manifest file, its current-record binding, and the manifest hash of each package file actually consumed by the projection (currently `meta.json`) without re-hashing every package byte. It isolates a corrupt managed record from the remaining index projection and returns a bounded diagnostic for each skipped record. Resolving an individual paper or explicit managed generation still performs full inventory hashing and fails closed on any missing, extra, modified, symlinked, or special file. This keeps one damaged paper from blocking unrelated publication while preserving the strong per-paper read boundary.

Published package files and directories are permission-sealed. Lifecycle code must first remove current/index authority under the storage locks and then call the explicit no-follow `unsealGenerationPackageForLifecycle(..., { authorized: true })` helper before deletion. C2b does not expose a delete command; retention and purge policy remain P1-7 work.

Recovery re-applies package sealing unconditionally after locating either a staged new-paper payload or an existing-record generation. A crash after rename but before the first chmod therefore cannot leave the eventually published generation writable. Lifecycle unsealing additionally requires a canonical containment root; symlinked roots, ancestors, package paths, descendants, and special files fail closed.

Every `publication.json` corruption class is isolated to its own workspace. Invalid JSON/schema/state, oversized files, symlinks, and non-regular entries produce a bounded `publicationInvalid` diagnostic; workspace listing and recovery continue with unrelated transactions.
